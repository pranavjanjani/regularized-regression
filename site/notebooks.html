Two tracks. The starter notebooks provide the scaffolding, data loading and plotting, with the estimators left as raise NotImplementedError. The solution notebooks are complete and already executed. Use them to check yourself, not to start.

Running them

Everything runs on NumPy, pandas, Matplotlib and scikit-learn. In Colab, upload uber_surge_mumbai.csv and new_city_features.csv alongside the notebook; locally, keep them in a data/ folder next to it. If a CSV is missing the notebook regenerates it from the same seed.

Conventions used in the code

ConventionWhy
Objective is $\frac{1}{2n}\lVert y-Xw\rVert^2 + \alpha\rho\lVert w\rVert_1 + \frac{\alpha(1-\rho)}{2}\lVert w\rVert_2^2$ Identical to scikit-learn's ElasticNet, so your solver and the library agree to machine precision. The $1/2n$ matters.
Ridge closed form uses $\alpha_{\text{sklearn}} = n\alpha$ sklearn.Ridge omits the $1/n$. This factor is the most common reason a path plot looks shifted.
Standardize on the training split only, then apply to test Computing the mean and sd over all 200 trips leaks test information into training. A small effect here, a bad habit elsewhere.
Time-based split, never shuffled Rows are in time order. A random split lets the model see the future.
np.linalg.solve(A, b) rather than inv(A) @ b Faster and numerically better conditioned. The explicit inverse appears exactly once, in Task 1, because there you are asked to look at it.
Random seed fixed at 42 everywhere Bootstrap numbers should match the solution notebook exactly; if not, something else differs.
On using the solutions

They are published deliberately: checking an answer against a correct one is how people learn to debug numerical code. But a coordinate descent loop you have read is not one you can write. Attempt each cell first, and if you consult the solution, say so in your submission.

The same computations, without leaving the browser, are in the algorithm walkthroughs and the lab.
